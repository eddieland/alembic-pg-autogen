## Why

Alembic writes one `op.drop_index()` call for each index of a table that the same migration drops. PostgreSQL removes
the indexes together with the table, so the calls do nothing. PostgreSQL also rejects `DROP INDEX` for a unique index
that a foreign key depends on, so a redundant call can fail the migration. The Alembic cookbook documents a
`process_revision_directives` hook that removes the calls. Every project copies the same twenty lines into its `env.py`.
This package can ship the hook once.

## What Changes

- Add `alembic_pg_autogen.rewriters` with `skip_drop_index_for_dropped_tables`, an Alembic `Rewriter`
- The rewriter removes each `DropIndexOp` whose `(table_name, schema)` matches a `DropTableOp` in the same `UpgradeOps`
  or `DowngradeOps` container, including entries nested in a `ModifyTableOps`
- A `ModifyTableOps` container that becomes empty is removed as well
- Export `skip_drop_index_for_dropped_tables` from the package root
- Document the hook in `README.md` and `docs/quickstart.rst`

The hook is opt-in. Alembic's plugin system only registers comparators, so `autogenerate_plugins` cannot enable a
`process_revision_directives` hook. The user passes the rewriter to `context.configure()`.

## Non-goals

- **Enabling the hook by default**: no Alembic extension point allows a plugin to install a
  `process_revision_directives` hook. The user configures it.
- **Other cookbook recipes**: this change ships one rewriter. Other recipes need their own proposal.
- **Removing other redundant operations**: the rewriter only removes `DropIndexOp`. Alembic already omits unique
  constraints for a dropped table.
- **Matching tables across schemas**: a `DropIndexOp` matches a `DropTableOp` only when both the table name and the
  schema are equal.

## Capabilities

### New Capabilities

- `revision-rewriters`: `Rewriter` objects that trim an autogenerated migration, starting with
  `skip_drop_index_for_dropped_tables`

### Modified Capabilities

- `library-foundation`: New `alembic_pg_autogen.rewriters` module; new `skip_drop_index_for_dropped_tables` public
  export

## Impact

- **Public API**: One new export. Additive; existing configurations behave exactly as before.
- **Behavior**: None unless the user passes the rewriter to `context.configure()`.
- **Docs**: README and quick start gain a "Skip `drop_index` for dropped tables" section.
- **Tests**: The test `env.py` forwards a `process_revision_directives` attribute so integration tests can opt in.
